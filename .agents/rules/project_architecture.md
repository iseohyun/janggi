# 웹장기 프로젝트 아키텍처 규칙

## 1. CSS 스타일링 정책 (2026-11-19 결정)
- **영역별 CSS 파일 방식**을 유지한다. `css/` 아래에 화면·기능 영역마다 파일 하나를 둔다
  (`base.css`, `board.css`, `modal.css`, `record.css` 등).
- 새 기능은 그 기능 이름의 CSS 파일을 새로 만들어 추가한다 (예: LLM 해설 → `css/ai-comment.css`).
- 한 영역의 스타일을 다른 영역 파일에 섞어 쓰지 않는다. 색·크기 같은 공통 값은 `base.css`에 둔다.

## 2. 이원화 버전 관리 및 캐시 버스팅 (2026-11-19 도입 결정)
- **캐시 버스팅 태그**: `YYYYMMDDvN` 형식 (예: `20261119v1`). 같은 날 여러 번 바꾸면 N을 올린다.
  - 배포 대상 파일(JS·CSS)을 고칠 때마다 AI가 자동으로 갱신한다.
  - `index.html`의 모든 `module/*.js`, `css/*.css` 주소 뒤에 `?v=<태그>`를 붙인다.
- **정식 버전(SemVer)**: `MAJOR.MINOR.PATCH`. 사용자 승인을 받은 경우에만 올린다.
  - 올릴 때는 CHANGELOG 초안을 먼저 대화창에 보여 주고 승인 후 기록한다.
- 두 값은 한 곳(버전 파일)에서 관리하고, 화면 어딘가(설정 패널 하단 등)에 표시한다.
  - 구체적 파일 위치는 도입 작업 때 확정해 이 문서에 기록한다.
